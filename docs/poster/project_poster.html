1. Abstract & Motivation

OVERVIEW

Modern enterprise vulnerability management suffers from severe alert fatigue and triage paralysis. Conventional port scanners (e.g., standard Nmap or raw banner matchers) produce vast numbers of unverified alerts, treating arbitrary version matches as confirmed vulnerabilities without assessing whether the bug is actively weaponized in the wild. Furthermore, unauthorized out-of-scope scanning poses acute legal liability under the Indian IT Act 2000 (Sec 43/66) and CFAA.

AEGIS-Recon bridges this gap by engineering a zero-trust, policy-governed network reconnaissance platform. It combines native subprocess security, multi-factor risk scoring, 4-tier cryptographic evidence provenance, and grounded threat intelligence to transform raw recon into actionable, verifiable defensive remediation.

3. Explainable Risk Scoring Engine

FORMULATION
Composite Priority Score Formulation (0 to 100):
Priority = [ w_cvss · S_cvss + w_kev · B_kev + w_epss · P_epss ] · C_asset · E_exposure
• S_cvss (40%): NIST NVD CVSS v3.1 base score normalized to [0, 100].
• B_kev (+25 Boost): Binary indicator of CISA Known Exploited Vulnerability.
• P_epss (+15 Boost): FIRST EPSS exploit probability in next 30 days.
• C_asset Context: Production=1.5×, Staging=1.2×, Dev=1.0×, Lab=0.8×.

4. Policy-Governed Scope Protection

ZERO-TRUST

AEGIS-Recon strictly prevents unauthorized target scanning and command injection through a dual-lock security gateway:

  • ✔ Subnet Authorization: Targets are validated against exact CIDRs in config/allowlist.yaml via Python ipaddress.ip_network.
  • ✔ Shell-Injection Defense: Subprocesses execute via list-based argument arrays with shell=False, completely neutralizing shell metacharacter injection (; & |).

6. 4-Tier Cryptographic Evidence Model

ZERO-TRUST

To prevent false accusations and hallucinations, findings follow a strict 4-tier chain of custody sealed with SHA-256 integrity digests:

TIER 1: OBSERVED
Direct wire telemetry (raw TCP SYN-ACK, banner bytes grabbed on port).
TIER 2: EXTERNAL INTEL
Authoritative feed data (NVD CVE descriptions, CISA KEV date, EPSS score).
TIER 3: HYPOTHESIS
Deductions requiring manual verification (e.g. Version match ≠ Exploit).
TIER 4: RECOMMENDATION
Actionable defensive mitigations derived solely from verified hypotheses.

7. 5-Level Resilient CPE Correlation

CORRELATION
Level 1: Exact CPE 2.3 Match (e.g., cpe:/a:apache:http_server:2.4.49) High Conf
Level 2: CPE Version Range (versionStartIncluding / EndExcluding) High Conf
Level 3: Vendor + Product + Version Token Match Med Conf
Level 4: Product + Version Regex Heuristics Med Conf
Level 5: Product-Only Fallback (Tagged as Hypothesis) Low Conf
